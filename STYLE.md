# Правила Library API

1. **Версия и URL.** Базовый путь `/v1/` задан в `servers`. Ресурсы — существительные
   во множественном числе: `/books`, `/readers`, `/loans`. Составные сегменты —
   kebab-case; идентификатор ресурса задаётся path-параметром `{id}`.
2. **Имена и представление.** JSON-поля — snake_case, типы стабильны.
   Тело — `application/json`; исключение — успешный DELETE с пустым 204.
3. **Методы.** GET читает, POST создаёт, PUT полностью заменяет редактируемые поля,
   PATCH меняет только переданные поля, DELETE логически удаляет ресурс.
   Возврат книги — отдельное действие POST `/loans/{id}/return`, история сохраняется.
4. **Схемы запросов.** Входные DTO отделены от выходных. Серверные поля отсутствуют
   во входных схемах; `additionalProperties: false` запрещает неизвестные поля.
   PATCH требует хотя бы одно поле. `available_copies` только readOnly в ответе.
5. **Время.** Даты — `YYYY-MM-DD`, моменты — RFC 3339 в UTC. Новая due_date строго
   позже текущей даты UTC. Просрочка начинается на следующую дату после due_date.
6. **Коллекции.** Фильтры объединяются через AND. Сортировка — `sort=title,-id`,
   затем limit/offset. При равенстве значений добавляется стабильный id ASC.
   Ответ: items и pagination с limit, offset, total. Пустая коллекция — 200.
7. **HTTP-статусы.** 200 — чтение/изменение/возврат, 201 + Location — создание,
   204 без тела — удаление, 400 — некорректный запрос, 404 — ресурс отсутствует,
   409 — конфликт состояния, 422 — ошибка схемы или динамического ограничения даты.
8. **Ошибки.** Описанные JSON-ошибки используют ErrorResponse: code, message,
   details, request_id. Код HTTP и машинный code имеют разное назначение.
   Детали указывают поле/параметр, сообщение понятно человеку. X-Request-ID помогает
   сопоставить запрос и ошибку. Ошибки mock 501 описаны отдельно в README.
9. **Бизнес-правила.** Остаток книги и лимит 5 активных выдач проверяются атомарно.
   Активная выдача — returned_at == null, включая просроченную. Книга или читатель
   с активной выдачей не удаляются; total_copies нельзя уменьшить ниже активных выдач.
10. **Идемпотентность.** POST `/loans` требует Idempotency-Key. Ответ хранится
    24 часа и полностью воспроизводится для того же тела. Иное тело — 409
    IDEMPOTENCY_MISMATCH; конкурентный запрос — 409 CONFLICT и Retry-After.
    Повтор возврата — 200 с неизменным returned_at, без повторного увеличения остатка.
