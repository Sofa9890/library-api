## Автоматические проверки

Команда `python verify_contract.py` проверяет:

- структуру OpenAPI 3.1 через openapi-spec-validator;
- все 77 использований примеров запросов/ответов по соответствующим JSON Schema;
- 7 отрицательных случаев: передача серверных полей, неверная дата и пустые PATCH;
- состав CRUD, URL, tags и уникальность operationId;
- единый ErrorResponse и соответствие code примеров описанным ответам;
- наличие фильтров, пагинации, overdue и обязательного Idempotency-Key;
- наличие описаний бизнес-правил и политики TTL/replay/concurrency.

Команды `ruff check .` и `ruff format --check .` проверяют Python-помощники.
Эти проверки не запускают настоящую выдачу книги и не доказывают транзакционную
корректность будущего сервиса. Правила с текущей датой, лимитом читателя и
конкурентностью должны исполняться и тестироваться при реализации сервера.

## Решения и границы

- Выбраны PUT и PATCH; PUT не создаёт ресурс по отсутствующему id.
- Удаление логическое: исторические выдачи сохраняют book_id и reader_id.
- Возврат повторяем без изменения returned_at и остатка второй раз.
- Полный replay сохраняет исходный прикладной ответ; только индикатор
  Idempotency-Replayed меняется. Транспортные заголовки могут формироваться заново.
- Динамический пример CreateLoan дан относительно 2026-10-30. При реальной выдаче
  нужно передать будущую дату относительно часов сервера, а не копировать старый пример.
- Mock показывает форму GET-ответов; CRUD, транзакции и идемпотентность в нём
  не реализованы. Для таких запросов он явно возвращает 501.
